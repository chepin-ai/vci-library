## §3 义务因果递归自推进（第三驱动）

权限约束驱动（工作流授权）与事实/事件驱动（dispatch/cron）之外，第三驱动：
**义务因果驱动**：义务 o 的未闭合状态本身是事件源——
```
自推进循环：o 未闭 → 年龄增长 → 价格上升（影子价格=年龄×权重） → 超过触发阈 → 自动派发清算任务 → 清算产出新证据/新残差 → 新义务 raised → …
```
- 与事件驱动的区别：事件是外部推入，义务因果是**内部生成**（系统的"欠账张力"直接做功）
- 形式：义务年龄场 A(o,t) 是标量场，其梯度 ∇A 驱动任务流；触发器=∇A 超阈（S3 的 tn_residual 场即其感官）
- 已实现度：阶梯升级（人域）已是义务因果的雏形；本卷立法将其推广为**全义务的通用驱动律**——oblig_tick 每轮的最老清算=∇A 最大者，这正是 FIFO 的热力学诠释：最老义务=最高势能
- **义务因果完备性猜想**：三类驱动（权限/事件/义务因果）对 CI-OS 全部可发生动作完备——任何动作的发起理由必属其一（权限=被允许，事件=被触发，义务=被要求）。∎（分类 exhaustiveness 论证同 NMUST-02 §1）

## §6 CI-OS 制度机器模型批判与融合方案

### 批判（基于 22 仓可读面）
1. **ci-* 与 vci-* 双体系的镜像开销**：56 个 disabled workflow（ci-control）说明镜像层有过载史——制度设计偏"全镜像"，缺"按需影子"（本卷 §4 的 HoloSense 即按需版）
2. **infra 单点**：私有仓额度耗尽即全中心停摆——义务机的降级面（usrm 执行+锚点双写）应推广为制度（任何中心件必有公域降级面）
3. **驱动单极**：旧制以 cron/event 为主，无义务因果驱动（§3 补齐）
### 融合方案（三层，不拆墙）
- 感知融合：HoloSense Φ 场从 vci-* 影子采集（现状即可）
- 驱动融合：义务因果驱动落在 vci-usrm（公域可审计），私域动作经 W5 影子驱动（HMAC 意图+回执）
- 制度融合：义务台账升格为联邦法（各仓 Gen 本地产生、ci-root 聚合、外部层审计）——**制度即义务机的建制化**
